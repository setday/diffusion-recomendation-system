# Contributing

Thanks for your interest in contributing to this project! Small, focused contributions and bug reports are very welcome.

How to contribute

- Report issues: open a clear issue with reproduction steps and expected behavior.
- Discuss large changes: open an issue first to propose major design or API changes.

Development workflow

1. Fork the repository and create a topic branch (`feature/` or `fix/`).
2. Follow the existing code style (use `black` for formatting).
3. Add or update tests where applicable.
4. Keep commits small and focused; write descriptive messages.
5. Open a pull request against the `main` branch and link related issues.

Testing and style

- Run the project's tests (if present) before submitting a PR.
- Apply automatic formatting: `black .`
- Linting: optionally run `flake8` or project linters.

Review process

- PRs will be reviewed for style, tests, and correctness.
- Maintainters may request changes; please iterate on feedback.

License and code of conduct

By contributing you agree that your contributions will be licensed under the project's `LICENSE`.
